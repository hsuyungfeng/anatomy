**Version**: 1.0
**Status**: DRAFT

## ADDED Requirements

### Requirement: 牙齒座標映射與點擊檢測

**Description**: 系統能夠識別牙齒圖像上特定位置的點擊，並自動映射到對應的牙齒編號。

**Compliance**: MUST

**Details**:
- 系統 MUST 支持永久牙編號系統 (Universal: 1-32)
- 系統 MUST 支持乳牙編號系統 (Universal: A-T)
- 系統 MUST 支持 FDI 國際編號系統
- 系統 MUST 達到 > 95% 的點擊準確率
- 系統 MUST 保持點擊檢測延遲 < 50ms

#### Scenario: 醫生點擊永久牙左上門牙

```
Given: 系統已加載永久牙圖像
When: 醫生在左上門牙 (#11) 位置點擊
Then:
  - 系統識別牙齒編號為 "11"
  - 顯示牙齒信息: "左上中門牙" (Upper Left Central Incisor)
  - 彈出病歷輸入表單
  - 牙齒區域視覺高亮 (綠色脈衝)
```

#### Scenario: 醫生點擊乳牙右上犬牙

```
Given: 系統已加載乳牙圖像
When: 醫生在右上犬牙 (D) 位置點擊
Then:
  - 系統識別牙齒編號為 "D"
  - 顯示牙齒信息: "右上犬牙 (乳)" (Right Upper Canine - Primary)
  - 彈出病歷輸入表單
  - 信息包含 FDI 編號轉換 (53)
```

#### Scenario: 醫生誤點非牙齒區域

```
Given: 系統已加載牙齒圖像
When: 醫生點擊圖像邊界或背景區域
Then:
  - 系統不觸發任何動作
  - 無錯誤提示 (靜默失敗)
  - 光標保持正常
```

### Requirement: 結構化病歷輸入表單

**Description**: 系統提供牙科特化的結構化表單，支持多層次的臨床信息輸入。

**Compliance**: MUST

**Details**:
- 系統 MUST 自動填充牙齒信息
- 系統 MUST 支持多個疾病分類選擇
- 系統 MUST 支持多個牙齒表面選擇
- 系統 MUST 支持嚴重程度分級 (無/輕/中/重)
- 系統 MUST 支持治療狀態追蹤 (未治/進行中/完成)
- 系統 MUST 實行表單驗證並提供錯誤提示

#### Scenario: 記錄牙齒蛀牙 - 單表面

```
Given: 醫生點擊牙齒 #11，表單已彈出
When: 醫生輸入以下信息:
  - 疾病: 齲齒 (caries)
  - 牙齒表面: 近心面 (mesial)
  - 嚴重程度: 中度 (moderate)
  - 臨床備註: "近端面初期齲齒，建議補綴"
  And 點擊「保存」按鈕
Then:
  - 表單數據驗證通過
  - 記錄保存到 localStorage
  - 圖像上標記牙齒 #11 為橙色 (中度問題)
  - 顯示成功通知: "牙齒 #11 病歷已保存"
  - 表單自動關閉
```

#### Scenario: 記錄牙齒蛀牙 - 多表面

```
Given: 醫生點擊牙齒 #14，表單已彈出
When: 醫生輸入以下信息:
  - 疾病: 齲齒 (caries)
  - 牙齒表面: [近心面, 咬合面] (多選)
  - 嚴重程度: 重度 (severe)
  And 點擊「保存」按鈕
Then:
  - 系統接受多個表面選擇
  - 記錄保存包含所有選定表面
  - 圖像上標記牙齒 #14 為紅色 (重度問題)
```

#### Scenario: 記錄牙周病

```
Given: 醫生點擊牙齒 #26，表單已彈出
When: 醫生輸入以下信息:
  - 疾病: 牙周病 (periodontal)
  - 嚴重程度: 輕度 (mild)
  - 治療狀態: 進行中 (in-progress)
  - 下次複診日期: 2025-01-16
  And 點擊「保存」按鈕
Then:
  - 記錄包含下次複診日期
  - 牙齒標記為黃色 (輕度問題)
  - 治療狀態在統計中反映
```

#### Scenario: 表單缺少必填字段

```
Given: 表單已彈出
When: 醫生未選擇「疾病」字段
  And 直接點擊「保存」按鈕
Then:
  - 系統顯示驗證錯誤: "請選擇疾病分類"
  - 表單不提交
  - 無法字段高亮為紅色
```

### Requirement: 牙科病歷存儲與管理

**Description**: 系統能夠按牙齒編號組織和存儲結構化病歷，支持多時間點追蹤和重複檢測。

**Compliance**: MUST

**Details**:
- 系統 MUST 按牙齒編號組織病歷 (32 個永久牙 + 20 個乳牙)
- 系統 MUST 支持每顆牙齒多個時間點的記錄
- 系統 MUST 實現自動重複檢測和衝突提示機制
- 系統 MUST 提供快速查詢和聚合功能
- 系統 MUST 使用 localStorage 實現本地持久化

#### Scenario: 首次記錄特定牙齒

```
Given: 牙齒 #11 之前無記錄
When: 醫生為牙齒 #11 輸入病歷並保存
Then:
  - 記錄以牙齒編號 "11" 為鍵存儲
  - 記錄包含完整元數據 (日期、醫生名、時間戳)
  - localStorage 中 "dental-records" 鍵已更新
```

#### Scenario: 追蹤同一牙齒的多次檢查

```
Given: 牙齒 #11 已有 2025-12-16 的蛀牙記錄
When: 醫生在 2025-12-20 為同一牙齒添加「已補綴」的記錄
Then:
  - 兩個記錄並存 (時間軸視圖)
  - 按時間順序存儲
  - 用戶可查看完整歷史
```

#### Scenario: 重複記錄檢測

```
Given: 牙齒 #11 已有 2025-12-16 的「齲齒 - 近心面 - 中度」記錄
When: 醫生嘗試添加相同牙齒 + 相同日期 + 相同診斷的新記錄
Then:
  - 系統檢測到重複
  - 顯示確認對話框:
    - "已存在相同記錄，是否覆蓋?"
    - [覆蓋] [保留舊] [保留新] [取消]
  - 用戶選擇「覆蓋」後，舊記錄被新數據替換
```

#### Scenario: 查詢整口牙概覽

```
Given: 系統已累積 8 顆牙齒的檢查記錄
When: 用戶請求「統計信息」面板更新
Then:
  - 總牙齒數: 32 (永久牙)
  - 已檢查數: 8
  - 問題分布:
    - 健康: 3 顆
    - 輕度問題: 2 顆
    - 中度問題: 2 顆
    - 重度問題: 1 顆
  - 數據實時更新，無延遲
```

### Requirement: 牙科病歷視覺化與標記

**Description**: 系統在牙齒圖像上視覺化顯示檢查狀態，用顏色編碼區分問題級別。

**Compliance**: MUST

**Details**:
- 系統 MUST 使用綠色標記健康/已檢查無問題的牙齒
- 系統 MUST 使用黃色標記輕度問題的牙齒
- 系統 MUST 使用橙色標記中度問題的牙齒
- 系統 MUST 使用紅色標記重度問題的牙齒
- 系統 MUST 使用灰色標記已治療完成的牙齒
- 系統 MUST 使用淺灰色標記未檢查的牙齒

#### Scenario: 標記已檢查的健康牙齒

```
Given: 醫生記錄牙齒 #8 的檢查: "無齲齒，無牙周病"
When: 記錄保存
Then:
  - 在牙齒圖像上，牙齒 #8 位置顯示綠色標記
  - 標記包含牙齒編號 "8"
  - 懸停時顯示「健康 - 無問題」
```

#### Scenario: 標記有多個問題的牙齒

```
Given: 牙齒 #14 有兩個記錄:
  1. 蛀牙 - 中度
  2. 牙周病 - 輕度
When: 系統計算整體嚴重程度
Then:
  - 取「最嚴重」的等級: 中度 → 橙色
  - 懸停時顯示: "蛀牙 (中度)、牙周病 (輕度)"
```

#### Scenario: 標記已治療的牙齒

```
Given: 牙齒 #11 有歷史記錄:
  1. 2025-12-16: 蛀牙 - 中度 (treatment: pending)
  2. 2025-12-20: 已補綴 (treatment: completed)
When: 系統評估最新狀態
Then:
  - 顯示灰色標記 (已治療完成)
  - 懸停時顯示: "已補綴治療 - 2025-12-20"
```

### Requirement: 多格式導出與報告生成

**Description**: 系統支持多種格式導出病歷數據，包括人類可讀的報告和標準化的醫療數據格式。

**Compliance**: MUST

**Details**:
- 系統 MUST 支持 JSON 格式導出 (完整結構化數據)
- 系統 MUST 支持 CSV 格式導出 (表格化數據)
- 系統 MUST 支持 FHIR 標準格式導出 (跨院互通)
- 系統 MUST 支持 HTML 報告生成 (可列印)
- 系統 MUST 支持 PDF 報告生成 (可郵件)

#### Scenario: 導出完整 JSON 格式

```
Given: 系統有 5 顆牙齒的檢查記錄
When: 用戶點擊「導出 JSON」按鈕
Then:
  - 生成 JSON 檔案結構:
    {
      "systemId": "dental",
      "type": "permanent",
      "teeth": {
        "11": { ... },
        "14": { ... },
        // ... 5 個牙齒
      },
      "exportDate": "2025-12-17T10:30:00Z",
      "patientId": "..."
    }
  - 檔案名: "dental-records-[patientId]-[date].json"
  - 用戶瀏覽器下載該檔案
```

#### Scenario: 導出 CSV 格式用於 Excel

```
Given: 系統有牙齒檢查記錄
When: 用戶點擊「導出 CSV」按鈕
Then:
  - 生成表格行:
    牙齒編號, 牙齒名稱, 診斷, 表面, 嚴重程度, 檢查日期, 備註
    11, 左上中門牙, 齲齒, 近心面, 中度, 2025-12-16, 初期齲齒
    14, 左上第一磨牙, 牙周病, , 輕度, 2025-12-16, ...
  - 檔案可直接在 Excel 中打開
  - 中文字符編碼正確 (UTF-8)
```

#### Scenario: 導出 FHIR 標準格式

```
Given: 系統有牙齒 #11 的蛀牙記錄
When: 用戶點擊「導出 FHIR」按鈕
Then:
  - 生成 FHIR Observation 資源:
    {
      "resourceType": "Observation",
      "status": "final",
      "code": {"text": "Dental Examination"},
      "bodySite": {"text": "Tooth #11"},
      "valueCodeableConcept": {"text": "齲齒 - 近心面 - 中度"},
      "effectiveDateTime": "2025-12-16T10:30:00Z"
    }
  - 符合 FHIR R4 標準
  - 可被他院系統導入
```

#### Scenario: 生成 HTML 病歷報告

```
Given: 系統有完整的檢查數據
When: 用戶點擊「生成報告」按鈕
Then:
  - 生成專業的 HTML 報告:
    - 報告頭: 患者信息、檢查日期、醫生簽名欄
    - 牙齒圖表: 彩色編碼的整口牙概覽
    - 詳細清單: 逐牙的診斷和治療建議
    - 備註: 總結和建議
  - 報告格式符合牙科行業標準
  - 支持列印預覽和 PDF 轉換
```

### Requirement: 響應式設計與多設備支持

**Description**: 系統在桌面、平板、手機上都提供良好的用戶體驗。

**Compliance**: MUST

**Details**:
- 系統 MUST 在桌面 (> 1024px) 提供三列布局 (圖像 + 統計 + 表單)
- 系統 MUST 在平板 (480-1024px) 提供二列布局 (垂直堆疊)
- 系統 MUST 在手機 (< 480px) 提供單列布局 (全寬)
- 系統 MUST 實現觸摸友好的交互元素
- 系統 MUST 確保所有設備上的文字可讀性 (最小 12pt)

#### Scenario: 在桌面上查看完整介面

```
Given: 用戶在 1920x1080 桌面設備上打開系統
When: 頁面加載完成
Then:
  - 左側: 牙齒圖像 (寬度 60%)
  - 右側: 統計面板和快速導航 (寬度 40%)
  - 所有元素清晰可見，無重疊
  - 縮放和重置控制按鈕易於操作
```

#### Scenario: 在平板上查看介面

```
Given: 用戶在 iPad (768x1024) 上打開系統
When: 頁面加載完成
Then:
  - 頁面垂直堆疊
  - 頂部: 牙齒圖像 (全寬)
  - 中部: 統計和快速導航
  - 底部: 操作按鈕
  - 圖像自動縮放以適應寬度
  - 表單彈窗在手指易觸及的位置
```

#### Scenario: 在手機上查看介面

```
Given: 用戶在 iPhone 12 (390x844) 上打開系統
When: 點擊牙齒並彈出表單
Then:
  - 牙齒圖像佔據上半部分
  - 表單彈窗佔據下半部分，可滑動
  - 所有表單字段可用一個指尖點擊
  - 標籤和按鈕文字清晰可讀 (≥12pt)
  - 表單提交後自動滑動回圖像區
```

### Requirement: 無障礙性支持

**Description**: 系統符合 WCAG 2.1 AA 標準，支持鍵盤和屏幕閱讀器。

**Compliance**: MUST

**Details**:
- 系統 MUST 提供完整的 ARIA 標籤和描述
- 系統 MUST 支持鍵盤導航 (Tab, Enter, Escape 等)
- 系統 MUST 維持顏色對比度 ≥ 4.5:1 (WCAG AA)
- 系統 MUST 支持屏幕閱讀器訪問
- 系統 MUST 通過 WCAG 2.1 AA 符合性檢測

#### Scenario: 使用鍵盤進行完整操作

```
Given: 用戶使用鍵盤而不使用滑鼠
When: 按下 Tab 鍵遍歷頁面元素
Then:
  - 系統選擇按鈕具有清晰的焦點指示 (邊框/背景變化)
  - 所有交互元素都可通過鍵盤激活
  - 圖像區域可通過 Tab 訪問，並顯示牙齒區域的鍵盤快捷鍵提示
```

#### Scenario: 屏幕閱讀器用戶操作

```
Given: 視障用戶使用屏幕閱讀器 (如 NVDA)
When: 用戶瀏覽頁面元素
Then:
  - 屏幕閱讀器朗讀每個元素的標籤和目的
  - 「統計信息」面板描述: "總計 32 顆牙齒，已檢查 8 顆，其中 2 顆有問題"
  - 系統類型切換: "當前: 永久牙系統，可按 Enter 切換為乳牙"
  - 表單彈出時: "牙齒 11 左上中門牙的病歷輸入表單已打開"
```

### Requirement: 多語言支持

**Description**: 系統支持繁體中文和英文，用戶可切換語言。

**Compliance**: MUST

**Details**:
- 系統 MUST 預設使用繁體中文
- 系統 MUST 支持繁體中文和英文兩種語言
- 系統 MUST 提供牙齒名稱的中英翻譯
- 系統 MUST 提供疾病分類的中英翻譯
- 系統 MUST 允許用戶切換語言並保存偏好設定
- 系統 MUST 生成中文或英文版本的報告

#### Scenario: 用戶切換為英文

```
Given: 系統以繁體中文顯示
When: 用戶點擊語言切換按鈕並選擇「English」
Then:
  - 整個介面切換為英文
  - 牙齒標籤: "11 - Upper Left Central Incisor"
  - 表單標籤變為英文
  - 疾病分類翻譯為英文: "Dental Caries", "Periodontal Disease"
  - 用戶偏好儲存在 localStorage，下次打開保留英文
```
