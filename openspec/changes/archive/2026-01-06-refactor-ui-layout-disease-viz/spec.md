## 🎯 Capability 1: 牙齿系统分离显示

### Requirement: 永久齿与乳齿独立标签页

**Description**:
在牙齿系统中添加永久齿和乳齿的独立标签页，允许用户在两个系统之间快速切换。

#### Scenario: 切换永久齿系统
```
Given: 用户在医疗记录应用中
When: 用户点击左侧「永久齒」标签页
Then:
  - 应显示 32 颗永久齿的图表
  - 右侧病歷列表应仅显示永久齒系统的记录
  - 该标签页应高亮显示为激活状态
  - 所有互动功能应正常工作
```

#### Scenario: 切换乳齿系统
```
Given: 用户在医疗记录应用中
When: 用户点击左侧「乳齒」标签页
Then:
  - 应显示 20 颗乳齿的图表（A-T 标记）
  - 右侧病歷列表应仅显示乳齒系统的记录
  - 该标签页应高亮显示为激活状态
  - 数据和状态应正确保留
```

#### Scenario: 保持状态持久化
```
Given: 用户在永久齒标签页有多条记录
When: 用户切换到乳齒标签页，然后返回永久齒标签页
Then:
  - 永久齒系统的所有记录应仍然存在
  - 连接线和可视化应正确重建
  - 用户之前的交互状态应被保留
```

**Requirements**:
- ✅ UI 支持两个标签页
- ✅ 支持快速切换
- ✅ 状态管理正确
- ✅ 数据持久化
- ✅ 响应式设计

**Acceptance Criteria**:
- [ ] 标签页清晰可见
- [ ] 点击响应快速（< 200ms）
- [ ] 标签页样式与系统一致
- [ ] 无数据丢失风险

## 🎯 Capability 2: 疾病可视化连接线

### Requirement: 牙齿与疾病的视觉关联

**Description**:
在牙齿图表上显示从牙齿到疾病的连接线，使用颜色编码和疾病名称标签，直观展示牙齿与疾病的关联关系。

#### Scenario: 单个牙齿的疾病显示
```
Given: 左上第一门牙有一条诊断记录（K02 牙根龋齿）
When: 用户查看牙齿图表
Then:
  - 应在该牙齿上显示一条橙色连接线
  - 连接线末端应显示「牙根龋齒」文本标签
  - 悬停时应高亮显示该连接线
  - 标签颜色应与 ICD-10 代码对应的颜色一致
```

**颜色映射表**:
```
K00 (牙齿发育及萌发疾患)    → #FF6B6B (红色)
K01 (埋伏牙)               → #FF8E72 (橙红)
K02 (牙根龋齿)             → #FFA500 (橙色)
K03 (牙齿硬组织其他疾病)   → #FFD700 (金色)
K04 (急性根尖牙周组织炎)   → #FF69B4 (热粉红)
K05 (齿龈炎及牙周疾病)     → #00CED1 (深青色)
K06 (牙龈腫大)             → #87CEEB (浅蓝)
K08 (牙齿及支持性构造其他疾患) → #8A2BE2 (蓝紫)
```

#### Scenario: 多疾病关联显示
```
Given: 左下第一臼齿有两条诊断记录（K02 和 K05）
When: 用户查看牙齿图表
Then:
  - 应显示两条连接线，分别为橙色和深青色
  - 两条线应以适当间距排列，避免重叠
  - 都应显示对应的疾病中文名称
  - 鼠标悬停时都应高亮
```

#### Scenario: 连接线交互
```
Given: 多条连接线显示在牙齿图表上
When: 用户悬停在某条连接线上
Then:
  - 该连接线应变亮或增加线宽
  - 对应的疾病标签应突出显示
  - 其他连接线应降低透明度
  - 信息提示应显示疾病代码和名称
```

**Requirements**:
- ✅ 连接线计算准确
- ✅ 颜色映射正确
- ✅ 支持多疾病显示
- ✅ 清晰的标签显示
- ✅ 流畅的交互反馈

**Acceptance Criteria**:
- [ ] 连接线起点与牙齿圆心对齐
- [ ] 标签位置合理，不与其他元素重叠
- [ ] 颜色准确对应 ICD-10 代码
- [ ] 性能良好（100+ 标注时 < 500ms 渲染）
- [ ] 在各浏览器中显示一致

## 🎯 Capability 3: UI 面板简化

### Requirement: 移除 OCR 和 JSON 导出功能

**Description**:
从用户界面中移除 OCR 上传功能和 JSON 导出选项，简化右侧操作面板，专注于核心功能。

#### Scenario: 移除 OCR 标签页
```
Given: 用户打开医疗记录应用
When: 用户查看右侧病歷管理区域
Then:
  - 不应显示「OCR 上傳」标签页
  - 仅显示「病歷列表」标签页
  - 「病歷列表」应自动激活
  - 界面整洁清晰
```

#### Scenario: 简化导出选项
```
Given: 用户完成病歷记录
When: 用户查看底部操作按钮
Then:
  - 应仅显示「匯出文字」按钮
  - 不应显示「匯出 JSON」按钮
  - 应显示「清空」按钮
  - 按钮布局美观均衡
```

#### Scenario: 导出功能仍可用
```
Given: 用户拥有病歷数据
When: 用户点击「匯出文字」按钮
Then:
  - 应下载格式化的文本文件
  - 文件包含完整病歷信息
  - 格式清晰易读
  - 文件名包含时间戳
```

**Requirements**:
- ✅ 完全移除 OCR 相关代码
- ✅ 保留必要的导出功能
- ✅ UI 布局清晰
- ✅ 无遗留代码

**Acceptance Criteria**:
- [ ] OCR 代码完全移除
- [ ] 无遗留的 OCR 事件监听
- [ ] JSON 导出代码保留但 UI 按钮移除
- [ ] 不存在无效的 UI 引用
- [ ] 界面加载无错误

## 🎯 Capability 4: 文本导出格式优化

### Requirement: 结构化时间轴导出格式

**Description**:
改进文本导出格式，使用结构化的时间轴视图，清晰展示病歷历史和统计信息。

#### Scenario: 导出单条记录
```
Given: 用户拥有一条牙齿诊断记录
When: 用户点击「匯出文字」并保存文件
Then: 文件应包含以下内容
  - 文件标题「醫療結構化病歷報告」
  - 病歷 ID 和患者 ID
  - 创建和更新时间戳
  - [治療時間軸] 部分
  - 记录的位置、疾病、摘要
  - [統計信息] 部分
```

**格式示例**:
```
醫療結構化病歷報告
=====================================

病歷 ID: a1b2c3d4-e5f6-4g7h-8i9j-0k1l2m3n4o5p
患者 ID: P123456
創建時間: 2025-12-31 10:30:00
更新時間: 2025-12-31 14:45:30

[治療時間軸]
=====================================

2025-12-31 14:30 - 左上第一門牙
  疾病: K02 牙根龋齒
  摘要: 初期龋齒，建議補綴
  ─────────────────────────

[統計信息]
=====================================
總標註數: 1
系統數量: 1 (牙齒系統)
疾病種類: 1
```

#### Scenario: 导出多条记录
```
Given: 用户拥有多条诊断记录
When: 用户点击「匯出文字」
Then: 文件应
  - 按时间倒序显示所有记录（最新在前）
  - 每条记录使用分隔符清晰分界
  - 所有信息完整准确
  - 格式一致统一
```

#### Scenario: 导出中文字符正确显示
```
Given: 病歷包含中文疾病名称和摘要
When: 用户导出为文本文件
Then:
  - 所有中文字符正确显示（无乱码）
  - 特殊符号（分隔线）正确显示
  - 文件编码为 UTF-8
```

**Requirements**:
- ✅ 结构化格式
- ✅ 完整信息
- ✅ 中文支持
- ✅ 易读性好
- ✅ 时间顺序正确

**Acceptance Criteria**:
- [ ] 导出文件包含所有必要信息
- [ ] 格式完全按照规范
- [ ] 时间轴按倒序显示
- [ ] 中文显示无乱码
- [ ] 文件可直接阅读和打印
