# Spec Delta: 牙齒系統分離與疾病可視化

## ADDED Requirements

### Requirement: 永久齒與乳齒獨立標籤頁

系統SHALL在牙齒系統中添加永久齒和乳齒的獨立標籤頁，允許用戶在兩個系統之間快速切換。

#### Scenario: 切換永久齒系統
- **WHEN** 用戶點擊左側「永久齒」標籤頁
- **THEN** 應顯示 32 顆永久齒的圖表，右侧病歷列表應僅顯示永久齒系統的記錄，該標籤頁應高亮顯示為激活狀態

#### Scenario: 切換乳齒系統
- **WHEN** 用戶點擊左側「乳齒」標籤頁
- **THEN** 應顯示 20 顆乳齒的圖表（A-T 標記），右侧病歷列表應僅顯示乳齒系統的記錄，該標籤頁應高亮顯示為激活狀態

#### Scenario: 保持狀態持久化
- **WHEN** 用戶在永久齒標籤頁有多條記錄後切換到乳齒標籤頁，然後返回永久齒標籤頁
- **THEN** 永久齒系統的所有記錄應仍然存在，連接線和可視化應正確重建

---

### Requirement: 牙齒與疾病的視覺關聯

系統SHALL在牙齒圖表上顯示從牙齒到疾病的連接線，使用顏色編碼和疾病名稱標籤，直觀展示牙齒與疾病的關聯關係。

#### Scenario: 單個牙齒的疾病顯示
- **WHEN** 用戶查看有一條診斷記錄（K02 牙根齲齒）的牙齒圖表
- **THEN** 應在該牙齒上顯示一條橙色連接線，連接線末端應顯示「牙根齲齒」文本標籤，懸停時應高亮顯示該連接線

#### Scenario: 多疾病關聯顯示
- **WHEN** 用戶查看有兩條診斷記錄（K02 和 K05）的牙齒圖表
- **THEN** 應顯示兩條連接線，分別為橙色和深青色，兩條線應以適當間距排列，都應顯示對應的疾病中文名稱

#### Scenario: 連接線交互
- **WHEN** 用戶懸停在某條連接線上
- **THEN** 該連接線應變亮或增加線寬，對應的疾病標籤應突出顯示，其他連接線應降低透明度

---

### Requirement: 移除 OCR 和 JSON 導出功能

系統SHALL從用戶界面中移除 OCR 上傳功能和 JSON 導出選項，簡化右側操作面板。

#### Scenario: 移除 OCR 標籤頁
- **WHEN** 用戶打開醫療記錄應用
- **THEN** 不應顯示「OCR 上傳」標籤頁，僅顯示「病歷列表」標籤頁，「病歷列表」應自動激活

#### Scenario: 簡化導出選項
- **WHEN** 用戶查看底部操作按鈕
- **THEN** 應僅顯示「匯出文字」按鈕，不應顯示「匯出 JSON」按鈕，應顯示「清空」按鈕

#### Scenario: 導出功能仍可用
- **WHEN** 用戶點擊「匯出文字」按鈕
- **THEN** 應下載格式化的文本文件，文件包含完整病歷信息，格式清晰易讀

---

### Requirement: 結構化時間軸導出格式

系統SHALL改進文本導出格式，使用結構化的時間軸視圖，清晰展示病歷歷史和統計信息。

#### Scenario: 導出單條記錄
- **WHEN** 用戶點擊「匯出文字」並保存文件
- **THEN** 文件應包含文件標題「醫療結構化病歷報告」、病歷 ID、患者 ID、創建和更新時間戳、[治療時間軸] 部分、記錄的位置疾病摘要、[統計信息] 部分

#### Scenario: 導出多條記錄
- **WHEN** 用戶有多條診斷記錄並點擊「匯出文字」
- **THEN** 文件應按時間倒序顯示所有記錄（最新在前），每條記錄使用分隔符清晰分界，所有信息完整準確

#### Scenario: 導出中文字符正確顯示
- **WHEN** 用戶導出包含中文疾病名稱和摘要的病歷為文本文件
- **THEN** 所有中文字符應正確顯示（無亂碼），特殊符號（分隔線）應正確顯示，文件編碼為 UTF-8
